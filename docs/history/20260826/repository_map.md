# Repository map

This repository separates three different kinds of material:

1. **release-facing reproducibility tools and panel data**, intended for a
   reviewer or reader;
2. **inventoried original analysis scripts**, preserved under `pipeline/` with
   provenance and known limitations;
3. **generated outputs**, which should be written outside the tracked source
   tree unless they are explicit release artifacts.

check the tagged release and `pipeline/ORIGIN_MANIFEST.tsv`.

## Reader paths

### I want to verify the manuscript quickly

Read `docs/reproduce_figures.md`, then run:

```bash
python scripts/validate_release.py --root .
python scripts/reproduce_figures.py \
  --all \
  --data-dir data/panels \
  --output-dir outputs/figures
```

This path validates the released panel data and regenerates the supported
computational plots. It does not retrain the model.

### I want to retrain or run inference

Read `docs/reproduce_model.md`, then locate the relevant original script in
`pipeline/ORIGIN_MANIFEST.tsv`. Start from released embeddings and split
manifests when available; regenerate ESM-C, PST, or SaProt embeddings only when
the required external weights, structures, versions, and compute resources have
been resolved.

### I want to audit data provenance or licences

Read `docs/data_sources.md`. It distinguishes third-party data/models/software
from benchmark labels, predictions, source data, checkpoints, and database files
generated by this study. Any **TO BE CONFIRMED** field is unresolved and must
not be replaced with an assumed current version.

### I want to understand what cannot yet be reproduced

Read `docs/known_limitations.md` before making an end-to-end reproducibility
claim. It records manual/external panels, missing derivations, historical label
inversions, hard-coded counts, numerical ambiguities, environment gaps, and
large-asset limitations.

## `configs/paper.yaml`

This human-readable configuration summarizes manuscript-critical constants:
the benchmark counts and filters, random seed, principal ensemble settings,
reported AUROC/AUPRC, screening thresholds, and database validation targets.
It is the release reference for those constants, but it is not yet a complete
machine-executable training configuration: model checkpoint revisions,
architecture and optimizer details, frozen train/held-out membership, and
external data snapshots remain separate requirements.

## `data/model_inputs/`

This directory contains six one-accession-per-line UniProt identifier sets:

| File | Records | Meaning |
|---|---:|---|
| `recurrent_positive_ids.txt` | 407 | Recurrent proteins before final quality and redundancy filters |
| `significant_positive_ids.txt` | 376 | Final positive benchmark |
| `negative_ids.txt` | 9,109 | Final negative benchmark |
| `potential_positive_ids.txt` | 1,879 | Potential-positive group |
| `untrained_proteome_ids.txt` | 5,649 | Reviewed human discovery universe released here |
| `high_confidence_candidate_ids.txt` | 342 | Candidates retained at the adopted 0.85 threshold |

These files define manuscript groups and can seed sequence retrieval or
downstream inference. They are not train/held-out split manifests and do not
replace the per-round negative-sampling records needed for an exact historical
retrain. `data/model_inputs/README.md` gives the local usage example and the
database-snapshot caveat.

## `data/panels/`

This directory contains small, panel-level CSV inputs for the fast figure
route. Files should use final manuscript identifiers and include enough columns
to recompute the plotted statistic, not only preformatted labels.

The release uses the final manuscript names, for example:

```text
Figure1b.csv
Figure2b.csv
Figure3e.csv
SuppFigure2c_ratio.csv
SuppFigure2c_rounds.csv
SuppFigure3b.csv
SuppFigure5d_raw.csv
SuppFigure5d_stats.csv
SuppFigure5d_summary.csv
manifest.json
```

`Figure` denotes a main figure and `SuppFigure` a supplementary figure. The CLI
uses compact identifiers such as `Fig3e` and `SupFig2c`, while
`data/panels/manifest.json` maps them to the released CSV files. Do not create
`SuppFigure4` or `SuppFigure6` aliases for legacy assets: those figures do not
exist in the current manuscript.

The committed CSVs are release inputs. Maintainers can regenerate them from the
source-data workbooks with `scripts/export_source_data.py`; readers normally do
not need the binary workbooks. `data/panels/README.md` records the deliberate
Figure 1b and Figure 3a corrections and distinguishes plotted values from raw
external data.

## `scripts/`

### `download_uniprot_fasta.py`

Retrieves current UniProtKB FASTA records for one released accession list in
validated batches. It checks for duplicate requested identifiers and fails when
the returned record count differs from the requested count.

```bash
python scripts/download_uniprot_fasta.py \
  --ids data/model_inputs/significant_positive_ids.txt \
  --output data/external/significant_positive.fasta
```

This is a convenience acquisition tool, not a frozen historical snapshot.
Record the UniProt release, access date, and downloaded-file checksum for an
archival reconstruction.

### `extract_fasta_ids.py`

Extracts unique accession identifiers from standard or pipe-delimited FASTA
headers while preserving their first-seen order:

```bash
python scripts/extract_fasta_ids.py \
  <input-fasta> \
  <output-id-list>
```

### `export_source_data.py`

Maintainer utility that exports documented panel CSVs from the comprehensive
source-data workbook and the separately corrected Figure 1b workbook.

```bash
python scripts/export_source_data.py \
  --input <path-to-comprehensive-source-data-workbook> \
  --figure1b-input <path-to-corrected-v5-Figure-1b-workbook> \
  --output-dir data/panels
```

### `reproduce_figures.py`

Release-facing plotting entry point. It supports the full automatic set via
`--all` and individual supported panels via `--figure <panel-id>`. It should
refuse a manual/external panel rather than silently generating an unrelated
legacy plot.

### `validate_release.py`

Checks that required files are present and evaluates invariant counts and
reference results. Validation should include, where the corresponding release
files are available:

- benchmark counts of 376 positives and 9,109 negatives;
- a complete 6 × 10 model metric grid;
- principal AUROC/AUPRC 0.9925/0.9264;
- 342 candidates at threshold 0.85;
- RLBPPredDB totals of 20,075 human, 17,002 mouse, and 37,077 combined records;
- TOP1/P11387 score 0.999743;
- panel-data schemas and manuscript-numbering consistency.

The validator should report unresolved tests as skipped or unavailable, not as
passing.

## `pipeline/`

`pipeline/` preserves original analysis scripts. These files are grouped by
scientific stage, not by the legacy filesystem location. The current curated
inventory contains 44 Python scripts.

### `pipeline/ORIGIN_MANIFEST.tsv`

This is the authority for file provenance. Each published pipeline file has one
row recording `source_path`, `target_path`, SHA-256 checksum, whether it was
modified during curation, and a short preservation note. Scientific role and
manuscript mapping are described in the stage sections of this repository; exact
inputs and outputs are defined by each script's CLI/header. A file's presence
in `pipeline/` does not guarantee that it is runnable without external data or
path adaptation.

### `pipeline/embeddings/`

Expected content includes the original scripts for:

- ESM-C representation extraction;
- PST representation extraction;
- SaProt/Foldseek 3Di token generation;
- SaProt representation extraction;
- mouse structure acquisition.

These scripts are typically the most compute- and storage-intensive part of a
full reconstruction.

### `pipeline/modeling/`

Expected content covers:

- general downstream-classifier training;
- SaProt-650M-AF2 + MLP ensemble training;
- handcrafted-feature random-forest baseline;
- filtered/unfiltered and model cross-comparisons;
- general, four-human-group, and mouse inference;
- sampling-ratio/ensemble-round stability;
- alternative undersampling strategies.

The final manuscript configuration is 300 rounds with a 1:1 positive:negative
sample per round. Legacy defaults that differ from this are not authoritative.

### `pipeline/analysis/`

Expected content covers GO/domain enrichment, EpiFactors categories, LLPS
database overlap, MobiDB-lite disorder analysis, STREME motif analysis, and
amino-acid composition. These scripts depend on versioned external resources
listed in `docs/data_sources.md`.

### `pipeline/figures/`

This directory contains original panel-specific plotting code and plotting
intermediates. It is a provenance archive. The release-facing interface is
`scripts/reproduce_figures.py`, which normalizes final panel identifiers and
excludes unsupported manual panels.

### `pipeline/database/`

This directory contains the original scripts used to construct human, mouse,
and combined RLBPPredDB data and any runtime database representation. It does
not by itself reproduce the final browser screenshot or GitHub Pages
deployment. The current intermediate builder writes 15 columns including
`sequence`, while the runtime builder emits 14 fields and omits `sequence`; see
`docs/known_limitations.md` before describing the deployed schema.

## `outputs/`

All local regeneration should write to `outputs/` or another user-selected
directory. Recommended subdirectories are:

```text
outputs/
├── figures/
├── metrics/
├── predictions/
├── downstream/
├── database/
└── validation/
```

Avoid overwriting the committed `data/panels/` files during normal
reproduction. If a maintainer deliberately re-exports panel data, review the
diff, rerun the validator, and record the workbook hashes.

## Authority order when files disagree

Use this order:

1. final manuscript figure/table number and legend;
2. frozen release data and its checksum/provenance record;
3. `docs/reproduce_figures.md` and `docs/reproduce_model.md`;
4. `pipeline/ORIGIN_MANIFEST.tsv`;
5. legacy filename, directory name, or comments in the original script.

This order is necessary because the project underwent multiple figure-number
changes and some legacy names no longer match the v5 manuscript.
